## 1. 先说大结果

公司里每个 AI 员工干活时，背后都需要一套"发动机"：接收任务、思考、调用工具（读文件、跑命令）、看结果、再思考……直到把活干完。这套发动机就是 **agent-core**——全名 `@tricompany/agent-core`，版本 v0.1.0，代码放在 `TriCompany/packages/agent-core/`。

它的来历一句话讲清：公司研究透了 Claude Code（Anthropic 的 AI 编程助手）的核心工作原理后，没有照搬它的代码，而是**按同样的原理自己重新实现了一套**，并且按公司自己的需要做了改造。这条路线内部叫"种子资产重实现"。

现在谁在用它？两个地方：

- **TriLC**：装在你电脑上的"本地执行节点"（一个后台小服务），你在 TriPilot 插件里跟 AI 说话，真正驱动 AI 干活的就是它在调 agent-core。
- **TriRMC**：新部署的"主控中心"，也接入了同一套内核。

同一颗发动机，装在两种车上——这是理解整个体系最重要的一句话。

## 2. 公司为什么自己造，不直接用 Claude Code

| 原因 | 白话解释 |
| --- | --- |
| 模型自主 | Claude Code 只能配 Claude 家的模型；公司要用自己的模型通道（DeepSeek 系），省成本、可路由、坏了自己切备胎 |
| 形态不同 | CC 是给个人用的命令行工具；公司要的是"多台机器协同的公司形态"——本地节点 + 中央主控，必须内核能嵌进自己的服务里 |
| 治理需求 | 公司有 13 名 AI 员工，谁的岗位说明书、谁能批什么、谁向谁汇报，都要机器可校验；CC 没有这层"组织架构"概念 |
| 可控可审计 | 权限规则、安全红线这些关键逻辑握在自己手里，出问题能查能改，不等上游发版 |

同时公司也很清楚差距在哪：原版 CC 打磨多年，自研版 v0.1.0 还年轻，一些能力（比如长对话自动压缩）还没搬进内核，而是由外围程序代劳。教程不藏这些差异，04 版有完整清单。

## 3. 核心概念白话词典

**Agent 循环（loop）**
AI 干活的根本节奏：问模型 → 模型说要干什么 → 真去干 → 把结果告诉模型 → 再问模型……如此往复，直到模型说"做完了"。就像你吩咐一个助理：他说"我需要查个资料"，你去查了递给他，他看完再说下一步，直到给你最终答复。默认最多转 25 轮，防止停不下来。

**工具调用（tool call）**
模型本身只会生成文字，不能碰你的电脑。所谓"工具"，就是提前登记好的一批能力按钮：读文件、写文件、搜代码、跑命令……模型通过"点名+给参数"来按下按钮。注意：**内核只提供按钮面板（注册表），按钮本身是各产品装上去的**——所以 TriLC 有跑命令的工具，纯聊天场景可以一个工具都没有。

**轮次与会话（turn / session）**
一轮 = 问一次模型 + 执行这一批工具。会话 = 一串消息的历史记录。本内核管好转次，但**不管存历史**——存历史（会话持久化、断点恢复）是外围产品的责任。

**合同（contract）**
每个 AI 员工入职时的岗位说明书，写成机器能校验的 YAML 文件：叫什么名字、岗位职责、能批准什么、禁止什么、向谁汇报、用什么工具、风险多高。v3.0 格式严格校验，格式不对直接拒收——相当于"证件不齐不予入职"。13 名员工的定义都靠它。

**cron（定时调度）**
让员工在指定时间自动干活："每周日 23 点""每 5 分钟一次"。内核的调度器还带两个贴心设计：很多任务都定在整点时会自动错开几分钟（避免挤爆）；任务失败会自动按越来越长的间隔重试；一切正常时不反复打扰人。

**权限模式（permission mode）**
六档放权旋钮：从"每步都问我"（default），到"目录里的编辑自动同意"（acceptEdits）、"只准看不准改"（plan）、"目录内自动干但绝不跑命令"（dontAsk），一直到"全放开"（bypassPermissions）。外加一条铁律：碰 .git 目录、改 shell 配置这类高危动作，**任何模式下都会被拦下来要求人工确认**。

**层级（tier）**
员工的权限等级：main（正式工，全套工具）/ heartbeat（定时工，能写文件但不能跑命令）/ subagent（临时帮手，只能读）/ coordinator（调度员，只会派活）。等级不够按按钮会被拒绝，临时帮手还想再拉帮手？直接拦死（防套娃）。

**子代理（sub-agent）**
主员工干到一半说"这部分让帮手去查"，就 spawn 一个受限的小实例去干子任务，干完汇报即解散。它不是新东西，就是用更小的权限再跑一遍同一个循环。
