## 1. 30 秒定位

`@tricompany/agent-core`（`TriCompany/packages/agent-core/package.json:2-4`）是 TriCompany 的共享 agent 内核包：**一个 agent 循环 + 一套工具注册表 + 一层权限引擎 + 一个 cron 调度核 + 员工合同校验器**，外加消息守卫、进程监督器、子代理适配三件支撑。它是 Claude Code 核心能力"种子资产重实现"的落点——权限引擎直接吸收自 CC 2.1.88 vendor（各文件头 `CTO-003 P4T1: Absorbed from Claude Code 2.1.88 vendor`），cron 核吸收自 openclaw，循环体从 TriMC 抽取共享。

现役消费者两家：

- **TriLC daemon**：`TriLC/package.json:23` 以 `file:` 依赖引入；HTTP 面直接跑 agentLoop。
- **TriRMC**：`TriRMC/package.json:25` 引入；`TriRMC/src/agent-loop/loop.ts:1-16` 自称薄壳——"All while-loop logic ... now live in agent-core. TriMC is just the DI layer + re-exports"，把 context-builder/prompt-cache/tool-gater 通过依赖注入喂回内核。

## 4. 一次请求的端到端数据流

以现役链路"TriPilot 扩展发一条聊天消息"为例（真实代码坐标全部标注）：

```mermaid
sequenceDiagram
    participant TP as TriPilot 扩展
    participant APP as TriLC app.ts (/v1/messages)
    participant LOOP as agent-core agentLoop
    participant TM as trimodel ModelClient
    participant TOOLS as tools.ts 注册表
    participant PE as PermissionEngine

    TP->>APP: POST /v1/messages (model, messages, system, stream)
    APP->>APP: 转 internal Messages、注册请求自带工具为占位 handler (app.ts:1851-1863)
    APP->>APP: 组装 AgentLoopOptions：tier=main、permissionMode、规则合并、deps=plan 门禁 (app.ts:1874-1893)
    APP->>LOOP: for await (agentLoop(options))
    LOOP->>LOOP: yield loop_start（模型/tier/可用工具数/权限模式）
    LOOP->>PE: decide(toolName,args)（有 tool_calls 时）
    PE-->>LOOP: allowed / ask→onPermissionAsk 回调 / deny
    LOOP->>TM: modelClient.stream(model,messages,{tools})
    TM-->>LOOP: delta / tool_calls 分片 / usage
    LOOP-->>APP: content_delta / assistant_message 事件
    alt 有工具调用
        LOOP->>TOOLS: executeTool(name,args,{cwd})（120s race 超时）
        TOOLS-->>LOOP: JSON 字符串结果
        LOOP-->>APP: tool_result 事件；结果入 messages，turn+1 续转
    else 无工具调用
        LOOP-->>APP: loop_end(done,usageSummary)
    end
    APP-->>TP: Anthropic SSE 流式回写（app.ts:1909-1919）；JSON 模式先过消息守卫再回包（app.ts:1969-1983）
```

要点提醒：

- `/v1/messages` 收到的请求自带工具时，daemon 只登记定义并返回占位结果（`app.ts:1856-1863` 注释 "tool execution delegated to TriPilot client"）——真正执行在客户端回环；daemon 本地工具（如 shell_exec）走注册表真执行。
- JSON（非流式）模式最终回复必须通过 `validateMessage` 守卫，空头响应直接 HTTP 422（`app.ts:1966-1983`）。
- 另一条内部入口 `POST /internal/v1/agent`（`app.ts:2062` 起）：TriMC 连接正常时代理转发，否则本地直跑 agentLoop——这就是"本地执行节点"语义。

## 5. 如何跑起来与调试

### 5.1 构建与测试（内核仓）

```bash
cd TriCompany/packages/agent-core
npm run build     # tsc -p tsconfig.json → dist/
npm test          # 先 build 再 node --test "test/*.test.mjs"（package.json:16）
npm run clean     # rimraf dist
```

注意测试对象是 **dist 产物**而非源码（`test/contract-v3.test.mjs:1-3` 注释明说），改完源码必须重新 build 才反映到测试。合同测试的 fixture 在 `test/fixtures/`，包含 v1/v2 拒收、缺 io_contract、未知字段、坏 family 等负例——调权限或合同逻辑时先看这些例子。

前置：`trimodel` 是 `file:../../../TriModel` 本地依赖，TriModel 仓必须在位且已构建。

### 5.2 写一个最小消费脚本

```js
import { agentLoop, register } from '@tricompany/agent-core';

register({ function: { name: 'echo', parameters: {} } }, async (args) => JSON.stringify(args));

for await (const ev of agentLoop({
  model: 'tmv-deepseek-v4-pro',
  systemPrompt: '你是一个测试助手',
  messages: [{ role: 'user', content: '打个招呼' }],
  maxTurns: 5,
  permissionMode: 'default',      // 别学裸跑：显式给权限模式
})) {
  console.log(ev.type, ev);
}
```

### 5.3 起 TriLC daemon 观察全链路

```bash
cd TriLC && npm run build && trilc start
curl http://127.0.0.1:8711/healthz   # 看 trimc 连接态/cron/会话收割器状态（app.ts:1117-1153）
# 打一条消息（非流式）：
curl -X POST http://127.0.0.1:8711/v1/messages -H "content-type: application/json" \
  -d '{"model":"tmv-deepseek-v4-pro","max_tokens":1024,"messages":[{"role":"user","content":"你好"}]}'
```

常用调试旋钮（daemon 启动时读取，`app.ts:1014-1053`）：`TRILC_PERMISSION_MODE`（缺省 bypassPermissions）、`TRILC_ALLOW_RULES` / `TRILC_DENY_RULES`（CLI 规则）、`TRILC_ADD_DIRS`（权限边界附加目录）、`TRILC_PRINT_MODE=1`（非交互强制 ask→deny 且禁用 bypass）、`TRIMC_CONFIG_DIR`（cron 存储目录，job-store.ts:30-36）。

### 5.4 断点建议

三个最有信息量的断点位：`loop.ts` 主 while 入口（看每轮 state.messages 形状）、`decision-pipeline.ts` 各 step 返回处（看 decidedBy 审计值）、`supervisor.ts` close 处理器（看退出原因分类）。

## 6. 常见误区

1. **以为内核自带 read_file/Bash**——不带。空注册表起循环 = 模型没有任何工具可调；工具永远由宿主注册（tools.ts:1-6）。
2. **以为 auto-compact 在内核里**——不在。压缩是 TriLC 外包裹行为（详见 04 §15 第 2 条）。
3. **改源码不重跑 build 就 npm test**——测试吃 dist，结果永远是旧代码的。
4. **把教程当真源**——本文行号绑定 v0.1.0 快照；冲突时回到 `packages/agent-core/src/` 与 `docs/engineering/` 真源裁决。
5. **裸调 agentLoop 不传权限配置**——默认 bypassPermissions（loop.ts:340），本地实验可以，接入任何真实链路前必须显式收敛。
